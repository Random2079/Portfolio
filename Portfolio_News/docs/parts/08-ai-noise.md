## План F-A (чистка ленты) — делать по шагам

**Цель:** на вкладке «Новости» видеть, что шум, а что стоит глянуть — без «купи/продай» и без ломки текущей ленты.

**Решение по триггеру (зафиксировано в плане):**  
сначала **кнопка «Прогнать ИИ»** по сегодняшним новостям scope BCS.  
Авто в poller — **не в A**; можно добавить флагом позже (как «both»).  
Почему: дешевле, не жжёт API на каждый poll, проще отладить.

### A0 — Контракт данных (до UI)

| Поле | Тип | Смысл |
|------|-----|--------|
| `label` | `noise` \| `relevant` \| `dup` | итог фильтра |
| `urgency` | `low` \| `mid` \| `high` | только если `relevant` |
| `reason` | string ≤120 | почему так (для тултипа) |
| `model` | string | напр. `deepseek-chat` |
| `as_of` | ISO/local | когда прогнали |

Запрещено в ответе модели: «купи», «продавай», таргет цены, ордер.

**Хранение:** колонки на `news` (или маленькая `news_ai_cache` по `news.id`) + TTL не критичен: результат живёт, пока новость в БД; повторный прогон перезаписывает.

### A1 — Модуль LLM (без UI)

Файлы (ориентир):

- `portfolio_news/ai_noise.py` — промпт + `classify_news_item(...)` → dict  
- `portfolio_news/config.py` — `deepseek_api_key: str = ""`, `ai_noise_enabled: bool = False`  
- ключ только из `Portfolio_News/.env` (`DEEPSEEK_API_KEY`), **не** коммитить  

Скопировать паттерн вызова из `YouTube_Translator/ai_analyze.py` (HTTP JSON, без тащить весь YT-проект).

Вход в модель: `ticker`, `title`, опц. `source`, опц. короткий snippet если появится позже (сейчас в `NewsItem` только title/url).

Тесты: fixture JSON ответа модели → парсер label/urgency; без сети.

### A2 — API

| Метод | Зачем |
|-------|--------|
| `POST /api/news/ai-classify` | body: `{ "ids": [...]\|null, "today_only": true }` — прогон пачки (сегодня + BCS scope) |
| `GET /api/news` | добавить в ответ поля AI, если есть (иначе null) |
| query `?ai=hide_noise` | опционально сразу фильтровать шум на сервере |

Статус/прогресс: простой sync на первую версию (лимит пачки, напр. 20–40 за клик) **или** job как poll — если >10 сек. Для A достаточно sync + лимит.

Если ключа нет / `ai_noise_enabled=false` → 503/400 с понятным текстом, лента не ломается.

### A3 — UI (вкладка Новости)

В `dashboard-demo.html` панель `#panelNews`:

1. Чекбокс/тумблер **«Скрыть шум»** (localStorage) — клиентский фильтр по `label=noise`  
2. Кнопка **«Прогнать ИИ»** → `POST …/ai-classify` → reload ленты  
3. Бейджи на карточке новости: `шум` / `ок` / `дубль` + цвет; `urgency` мелким текстом  
4. Без ключа: кнопка disabled + подпись «задай DEEPSEEK_API_KEY в .env»

Лента без прогона = как сейчас (без бейджей или «—»).

### A4 — Проверка

```text
1. serve + .env с ключом, ai_noise_enabled=true
2. Новости → Прогнать ИИ → бейджи появляются
3. «Скрыть шум» — noise пропадают из вида
4. Без ключа / флаг false — лента жива, кнопка объясняет почему
5. pytest: парсер JSON + «нет ключа» не падает процессом
```

### A5 — Не в скоупе A

- Авто-classify в `poll_job` / toast  
- Разбор тикера (это **B**)  
- Чат  
- IDEA-023 forecast  
- Переписывать RSS-источники  

### Порядок кодинга (когда скажешь «делаем A»)

1. A0 схема БД + миграция `create_all`  
2. A1 `ai_noise.py` + конфиг + тесты парсера  
3. A2 эндпоинт classify + расширить `NewsOut` / `/api/news`  
4. A3 UI кнопка + бейджи + фильтр  
5. Смоук из A4 → «пробуй»  

Коммит пласта KS (до F) — **отдельным** коммитом до или сразу после старта A, не смешивать с F-A в одном диффе.

## B — разбор тикера (после A, кратко)

- Вход: тикер + свежие новости scope + опц. ярлыки KS (не весь Investing/).
- Выход JSON: на что бьёт / срочность / `checklist[]` вопросов к своей стратегии.
- Не ордер, не «купи/продай».
- UI: панель разбора, не чат.

## Чат (парковка)

- Зачем: не тащиться «хер пойми куда» за мелочью; у приложения уже есть данные.
- Не замена B; не прогноз (IDEA-023).

## Не делаем сразу

- Инвест-советы («покупай/продавай»).
- Замена RSS целиком на LLM.
- Прогноз цены / «куда купить» (IDEA-023).
- Полноценный чат в MVP F.
- Копипаст ключа в код.
- Авто-ИИ в poller на этапе A.

## Роль

Ты кодишь **утилиту мониторинга новостей по тикерам** в репо `DS_Projects`.  
Это **не** инвест-консультант: не советуй покупать/продавать, не тащи чек-поинт из воркспейса `Инвестиции/`.

## Канон

- Идея: `IDEAS.md` → IDEA-003  
- План: `.cursor/plans/IDEA-003-portfolio-news.md`  
- Код: `Portfolio_News/` (создать, если нет)  
- Один фокус: не параллелить Discord mute / VPN / TTS-апгрейды  
- Git: код + README + `.env.example` + plans/IDEAS; **не** коммитить `.env`, живые токены, `seen.json` с мусором если чувствительно

## Цель MVP

Тикеры из конфига → опрос источников → дедуп → одно уведомление (Telegram **или** Windows toast — одно на первую итерацию).

## Сделай по шагам

1. Каркас `Portfolio_News/`: `README.md`, `requirements.txt`, `.env.example`, `tickers.example.json`, `.gitignore`.
2. Загрузка тикеров + интервал из конфига.
3. Один источник новостей (документируй какой; если API ключ — только `.env`).
4. Store `seen` (файл/sqlite): ключ = hash(url) или (ticker+title).
5. Канал уведомлений — один. Telegram: `BOT_TOKEN` + `CHAT_ID`.
6. CLI: `python -m portfolio_news once` и `… watch` (или аналог).
7. Короткий README: как завести бота, куда писать тикеры, как гонять.

## Запреты

- Не строить React UI в MVP  
- Не подключать брокерские API «для полного портфеля» в первой итерации  
- Не обещать realtime биржевые котировки — только новости  
- Не коммитить секреты  
- Не раздувать scope («ещё и сентимент-ИИ и дашборд»)

## Definition of done

- 2–3 тикера в конфиге  
- `once` отрабатывает без падения  
- Новая новость → уведомление  
- Та же новость повторно → тишина  
- README позволяет поднять с нуля за <15 минут

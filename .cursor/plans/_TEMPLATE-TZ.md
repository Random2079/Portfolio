## Регрессия / тесты (обязательный блок)

### Зачем

Не культ TDD. Фиксируем **контракты на опасных стыках**, чтобы не ловить один баг дважды после «маленького фикса».

### Когда блок обязателен

Проект с **несколькими процессами / хуками / Stop / очередью / долгой загрузкой** — да.  
Одноразовый скрипт на 50 строк — «не применимо» одной строкой.

### Что писать

1. **Контракты** — 3–7 пунктов «если X, то Y» (не «протестировать всё»).
2. **Команда прогона** — одна строка unittest/pytest из корня проекта.
3. **Не тестируем автоматом** — звук, UI «на глаз», полный cold load в CI.
4. **Ручной смоук** — 3–5 шагов-блокеров перед «готово по правке».
5. **Политика агента** — меняешь стык X → гоняй эти тесты; нет теста → напиши минимальный.

### Пример формулировки контракта

- Stop при warmup≠cuda_engine → процесс жив.
- Дубль hook `generation_id` → одна постановка в очередь.
- Preview во время warming → запрещён.

### Чего не писать в ТЗ

- «Покрытие 80%»
- «Бэктесты от всех багов»
- Простыня про теорию тестирования

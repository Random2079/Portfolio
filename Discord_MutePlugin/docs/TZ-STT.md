# ТЗ — выбор распознавателя речи для VoiceMuteSlots (STT)

> Статус: **выбор движка, код mute/slots уже ✅**  
> Дата: 2026-08-25  
> Контекст: Vosk small + grammar / Whisper / Google Web Speech — пробовали, **надёжно не взлетело**. Мик при этом нормальный.

---

## 1. Цель (одно предложение)

Найти и зафиксировать **один** STT-путь, который на коротком PTT (Shift+K ~1.5–2.5 с) стабильно даёт текст вида «замутить / размутить + слот», чтобы парсер уже существующего плагина мог замутить нужный slot — **без OCR и без «угадайки»**.

---

## 2. Что уже доказано (не спорить заново)

| Факт | Доказательство |
|------|----------------|
| Мик **не** «тихий/битый» | `peak_rms` часто 12k–20k на Realtek; клипы громкие |
| Small Vosk **free** почти всегда мусор | «по самой четвёртого», «взломать», «замок второго» |
| Vosk **grammar** угадывает слот | FREE «четвёртого» → CMD «пятого» / «третья» |
| Короткий hold (~0.7–1.2 с) ломает всё | `wall_ms` / `pcm_ms` в debug-логах |
| Whisper на коротком PTT | тормоза + галлюцинации («Замутить пиво») |
| Big Vosk | долгая загрузка; **grammar не поддерживается** |
| Google free web | сеть; без таймаута Discord «зависал» на «Обрабатываю…» |
| Слоты / local mute | работают отдельно от STT (`SortedVoiceStateStore` + `toggleLocalMute`) |

**Вывод:** проблема не в Discord stores и не в «сломанном микрофоне». Проблема в **движке/режиме распознавания коротких русских команд**.

---

## 3. Продуктовые требования к STT

### Must (без этого «не готово»)

1. **Фраза → текст**, пригодный для `parseCommand` (глагол mute/unmute + слот 1…N словом или цифрой).
2. **Latency:** от отпускания Shift+K до текста **≤ 2.5 с** в 90% попыток (иначе UX «зависло»).
3. **Таймаут жёсткий:** если движок молчит → ошибка в HUD ≤ 8–15 с, Discord не фризится.
4. **Повтор:** из 10 спокойных попыток «замутить первого/второго/третьего» в тишине — **≥ 8 верных** (слот + действие).
5. **Локальный или контролируемый ключ:** либо офлайн, либо один явный API-ключ в конфиге (не «магический» free endpoint без SLA).
6. Тот же контракт демона: `POST /listen/start` → `POST /listen/stop` → `{ transcript, free_text?, peak_rms, … }`.

### Should

- Работает при лёгком фоне (вентилятор), не только в студии.
- Старт демона ≤ 30 с (не 2 мин как big Vosk).
- Переключение engine одной строкой в `stt_config.json`.

### Must not

- OCR / клики / Discord-бот.
- «Починить» small Vosk бесконечными костылями (VAD/grammar/offline) без смены класса движка.
- Требовать идеальный диктант свободной речи — нужны **команды**, не стенограмма болтовни.

## 4. Как выбирать движок (процедура, не «вайб»)

### Шаг A — бенч на своих клипах (1 вечер)

1. Взять **20 уже записанных** WAV из `stt/logs/clips/` (или записать 20 новых: 2 с, чётко, тишина).
2. Для каждого кандидата прогнать **один и тот же набор** offline (скрипт или ручной вызов).
3. Таблица:

| clip | сказали | engine X text | slot ok? | verb ok? | ms |
|------|---------|---------------|----------|----------|-----|

4. Победитель = max (slot∧verb), при latency ≤ 2.5 с.

### Шаг B — live PTT (только победитель)

1. Поднять демон с этим engine.
2. 10× Shift+K по сценарию слотов.
3. Смотреть HUD **только поле команды** (не «свободно» от Vosk).
4. Если < 8/10 — кандидат **убит**, следующий по списку.

### Шаг C — зафиксировать

- `stt_config.json`: `engine=…`
- Part `05-stt-engine.md`: почему выбран, как откатить.
- В основном `TZ.md` слой C → ✅ только после шага B.

## 5. Кандидаты (порядок проверки)

Не внедрять всё сразу. **Один кандидат → бенч → kill/keep.**

| # | Кандидат | Плюс | Минус | Когда убивать |
|---|----------|------|-------|----------------|
| 1 | **Yandex SpeechKit** (API, ru) | заточен под RU, нормальный SLA | нужен ключ/биллинг | <8/10 на бенче или >3 с |
| 2 | **Google Cloud Speech-to-Text** (официальный API) | качество | ключ, квота, не free web | то же |
| 3 | **Whisper medium/large-v3** + `initial_prompt` команд + **без** vad_filter на коротких клипах, GPU | офлайн, качество | CPU тормоза; раньше small уже провалился | latency >2.5 с или <8/10 |
| 4 | **Keyword / command spotter** (Porcupine custom / openWakeWord + свой словарный классификатор слотов) | идеально под «замутить N» | другая архитектура, не «диктант» | если за 1 спринт нет MVP |
| 5 | Vosk small + grammar | уже есть | **доказано слабо** | не выбирать снова как «основной» без нового класса модели |
| 6 | Google **Web Speech** free (`speech_recognition`) | быстро попробовать | нет SLA, зависания, блокировки | уже почти убит по UX |

**Рекомендуемый порядок:** 1 → 2 → 3 → 4. Пункты 5–6 — только fallback / эксперимент, не «надежда».

## 6. Архитектура (не ломать)

```
Discord plugin (Equicord)
  Shift+K → POST :39281/listen/start|stop
       ↓
  STT daemon (один процесс)
       ↓ transcript
  parseCommand.ts → localMute(slot)
```

Меняется **только** реализация decode в демоне (`engine=…`).  
Плагин / слоты / mute **не переписывать**, пока STT не прошёл §3 Must.
